LIVI exposes two global objects to the renderer via [`contextBridge`](https://www.electronjs.org/docs/latest/api/context-bridge): `window.projection` and `window.app`. Both are implemented in [`src/preload/index.ts`](https://github.com/f-io/LIVI/blob/fa5e341d76990a53f13cb7aea6431e17bf5504b3/src/preload/index.ts). This page documents every method, its IPC channel, and the buffering and replay rules that govern each subscription family.

## Invoke versus send

`invoke` is used for round-trip calls that return a `Promise`. `send` is used for fire-and-forget messages. There is no automatic reply for `send`; the main process must emit a separate event if a response is needed.

| Mode | Electron API | Typical use |
| --- | --- | --- |
| Request/response | `ipcRenderer.invoke` | Settings reads, device lists, transport switching |
| Fire-and-forget | `ipcRenderer.send` | Touch input, volume changes, activity pings |

## Global object comparison

Most projection and USB logic lives on `window.projection`. Platform metadata, system lists, and update/application controls live on `window.app`.

|  | `window.projection` | `window.app` |
| --- | --- | --- |
| Projection lifecycle | Yes | No |
| Touch/volume/media control | Yes | No |
| Settings, audio device enumeration | Yes | No |
| Platform and update surface | No | Yes |
| System list queries (Wi-Fi, Bluetooth, displays) | No | Yes |
| Media keys (listen and broadcast) | No | Yes |

The `appApi.compositor` flag is read from `process.env.LIVI_COMPOSITOR === '1'`; `appApi.platform` is `process.platform`.

## Subscription families and buffering policies

The preload layer implements four distinct policies for renderer-side subscriptions.

| Family | Channel | Queue type | Size/replay | Note |
| --- | --- | --- | --- | --- |
| USB events | `usb-event` | Unbounded queue | First subscriber drains all queued events | [`src/preload/index.ts`](https://github.com/f-io/LIVI/blob/fa5e341d76990a53f13cb7aea6431e17bf5504b3/src/preload/index.ts) (usbEventQueue) |
| Projection events | `projection-event` | Unbounded queue | First subscriber drains all queued events | [`src/preload/index.ts`](https://github.com/f-io/LIVI/blob/fa5e341d76990a53f13cb7aea6431e17bf5504b3/src/preload/index.ts) (projectionEventQueue) |
| Media keys | `app:media-key` | Unbounded queue of strings | First subscriber drains all queued commands | [`src/preload/index.ts`](https://github.com/f-io/LIVI/blob/fa5e341d76990a53f13cb7aea6431e17bf5504b3/src/preload/index.ts) (mediaKeyQueue) |
| Audio chunks | `projection-audio-chunk` | Bounded queue | Latest 32, drained once on first handler | [`src/preload/index.ts`](https://github.com/f-io/LIVI/blob/fa5e341d76990a53f13cb7aea6431e17bf5504b3/src/preload/index.ts) (audioChunkQueue) |
| Cluster resolution | `cluster-video-resolution` | Latest non-null value | Replayed to every new subscriber | [`src/preload/index.ts`](https://github.com/f-io/LIVI/blob/fa5e341d76990a53f13cb7aea6431e17bf5504b3/src/preload/index.ts) (lastClusterResolution) |
| Telemetry | `telemetry:update` | None | No replay, broadcast to all handlers | [`src/preload/index.ts`](https://github.com/f-io/LIVI/blob/fa5e341d76990a53f13cb7aea6431e17bf5504b3/src/preload/index.ts) (telemetryHandlers) |

All unbounded queues (USB, projection, media keys) buffer indefinitely until a subscriber appears. The audio queue is capped at 32 entries to prevent memory growth in windows that never show the visualizer. Telemetry has no queue and no replay; only real-time subscribers receive updates.

### Transport and devices

| Method | Signature | Mode | Main channel |

### Touch, commands, and events

| Method | Signature | Mode | Main channel |

| Method | Signature | Mode | Main channel |
| --- | --- | --- | --- |

| `setVisualizerEnabled` | `(enabled: boolean): void` | send | `projection-set-visualizer-enabled` |

### Audio chunk subscription

| Method | Signature | Policy |
| --- | --- | --- |
| `onAudioChunk` | `(handler: ChunkHandler): void` | Single handler, bounded 32 |
| `offAudioChunk` | `(handler: ChunkHandler): void` | Clears handler if it matches |

Only one handler can be registered at a time. Calling `onAudioChunk` replaces the previous handler and drains the current queue into the new handler. The payload shape is `unknown`; the main process defines the chunk format.

### Cluster

| Method | Signature | Mode | Main channel |
| --- | --- | --- | --- |
| `requestCluster` | `(enabled: boolean): Promise<{ ok: boolean; enabled: boolean }>` | invoke | `cluster:request` |
| `clusterRepaintNudge` | `(): Promise<{ ok: boolean }>` | invoke | `cluster:repaint-nudge` |
| `onClusterResolution` | `(handler: ChunkHandler): () => void` | listener | `cluster-video-resolution` |

`clusterRepaintNudge` is documented in source as macOS-only; it moves the window by one pixel to force a surface repaint for transparent-window cluster planes.

`onClusterResolution` replays the latest non-null payload to every new subscriber, so a late subscriber immediately knows whether a cluster stream is active.

| `offTelemetry` | `(handler: (payload: unknown) => void): void` | Removes matching handler |
| `getTelemetrySnapshot` | `(): Promise<unknown>` | invoke (`telemetry:snapshot`) |

### Media keys

| Method | Signature | Mode | Main channel |
| --- | --- | --- | --- |
| `broadcastMediaKey` | `(command: string): void` | send | `app:media-key` |
| `onMediaKey` | `(handler: (command: string) => void): () => void` | listener | `app:media-key` |

`broadcastMediaKey` sends a command to the main process, which then broadcasts it back to all renderer listeners via the same channel. `onMediaKey` uses the unbounded media-key queue. The first subscriber drains all queued commands.

## Remaining unknowns

The preload file only declares the renderer side of each channel. The following are not present in the bundle and are treated as unknown:

- Main process handlers for every channel listed above (implementation, payload validation, and error responses).
- Internal payload definitions, value ranges, and security boundaries.
- `Config`, `TransportSnapshot`, and `MultiTouchPoint` field-level definitions.
- Whether any `invoke` handler enforces schema validation before replying.

Only shapes explicitly written in `src/preload/index.ts` are guaranteed.
