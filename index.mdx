LIVI's supplied source bundle exposes six implementation boundaries: configuration loading, projection transport selection, telemetry state, software updates, Electron renderer IPC, and native media records. Use this guide to understand the rules implemented in those files, not to assume a complete application contract.

## Evidence and Boundaries

The bundle contains eight implementation files copied from `f-io/LIVI` at commit `fa5e341d76990a53f13cb7aea6431e17bf5504b3`, according to the supplied [provenance page](/README). Each topic cites the relevant file and symbols with immutable source links.

The TypeScript files show calls into dependencies whose implementations are not included. Their full types, validation rules, IPC handlers, platform installers, and runtime wiring remain **unknown** unless explicitly established by the supplied caller. Rust framing tests are evidence of the listed cases, not proof of end-to-end media compatibility.

The visible flow is local to each boundary: configuration returns a validated value; arbitration chooses a candidate without starting a session; Socket.IO inputs merge into the telemetry store and broadcast snapshots; the preload exposes IPC wrappers; the updater delegates installation; and the native framer turns bytes into records. Connections between these components that require omitted files are not asserted.
